# Intel 8080 → Game Boy (LR35902 / Sharp SM83) Conversion Guide

This document maps every existing Intel 8080 opcode in `GameboyEmulator.Core/Intel8080/`
to the action required to turn the core into the Game Boy's LR35902 CPU (also known as
the Sharp SM83 / LR35902 / DMG CPU). Cycle counts in this document are reported in
**T-states (machine clocks)** to match the existing 8080 implementation; the LR35902
is conventionally documented in M-cycles where 1 M-cycle = 4 T-states.

---

## 1. Primary opcode table (0x00–0xFF)

The full 256-entry primary opcode table — every 8080 byte mapped to its
LR35902 instruction, action (Keep/Modify/Replace/Delete), cycle count, and
flag effects — lives in **[`lr35902-opcode-tables.md`](lr35902-opcode-tables.md) §1**.

That file also contains:

- **§1.1** Summary counts (Keep / Modify / Replace / Delete) and the list of
  the 21 reused opcode bytes.
- **§1.2** The 11 illegal opcodes that must fault.

Quick reference for the rest of this document:

- The 21 **Replace** opcodes (where the byte stays but the meaning changes):
  `0x08, 0x10, 0x18, 0x20, 0x22, 0x28, 0x2A, 0x30, 0x32, 0x38, 0x3A, 0xCB,
  0xD9, 0xE0, 0xE2, 0xE8, 0xEA, 0xF0, 0xF2, 0xF8, 0xFA`.
- The 11 illegal opcodes:
  `0xD3, 0xDB, 0xDD, 0xE3, 0xE4, 0xEB, 0xEC, 0xED, 0xF4, 0xFC, 0xFD`.

## 2. The 0xCB-prefixed instruction table (256 new opcodes)

The full CB table — operation groups, per-operand cycle counts, and the
`(operation, operand)` decoder layout — lives in
**[`lr35902-opcode-tables.md`](lr35902-opcode-tables.md) §2**.

Highlights you need elsewhere in this document:

- 11 distinct operations: `RLC`, `RRC`, `RL`, `RR`, `SLA`, `SRA`, `SWAP`,
  `SRL`, `BIT n`, `RES n`, `SET n`. (Step 4 in §6 refers to "11 CB operations".)
- All register variants are 8 T; `(HL)` variants are 16 T except `BIT n,(HL)`
  which is 12 T (read only).
- The 4 T `0xCB` prefix fetch is already included in those totals — do not
  double-count.
- Flag effects across all CB shifts/rotates: `Z=result, N=0, H=0, C=shifted-out`.
- `BIT n,r`: `Z=!bit, N=0, H=1, C` unchanged. `RES`/`SET`: no flags.

## 3. Flag changes

### 3.1 Flag register layout

The current `CpuFlags` (`CpuFlags.cs`) is the 8080 PSW: `S Z 0 A 0 P 1 C`.
Replace it with the LR35902 layout:

```
bit:  7  6  5  4  3  2  1  0
flag: Z  N  H  C  0  0  0  0
```

- **Z** (Zero) — set when the result is 0.
- **N** (Subtract / Negative) — set after subtractive ALU ops (SUB, SBC, CP, DEC).
  Used by DAA to pick add-correct vs subtract-correct.
- **H** (Half-Carry) — set on carry/borrow from bit 3 to bit 4 (8-bit ops) or
  bit 11 to bit 12 (`ADD HL,rr`). This is the renamed AC flag.
- **C** (Carry) — set on carry/borrow from bit 7 (or bit 15 for `ADD HL,rr`).
- The low 4 bits of F are **always read as 0** and ignored on writes (relevant
  to `POP AF`).

**Removed**: Sign (S), Parity (P). Delete from `CpuFlags` and from every helper
that sets them.

Suggested rewrite of `CpuFlags.cs`:

```csharp
[Flags]
public enum CpuFlags : byte
{
    None = 0,
    C = 1 << 4,
    H = 1 << 5,
    N = 1 << 6,
    Z = 1 << 7,
    All = Z | N | H | C,
}
```

### 3.2 DAA

The 8080 DAA only "fixes" the result of additive BCD operations. The LR35902
DAA also handles subtraction by inspecting the **N** flag. The standard
implementation:

```
if N == 0:                       // last op was add
    if H or (A & 0x0F) > 9: A += 0x06
    if C or A > 0x9F:        A += 0x60; C = 1
else:                            // last op was sub
    if H: A = (A - 0x06) & 0xFF
    if C: A -= 0x60
Z = (A == 0); H = 0; (C as set above)
```

This requires that every ADD/ADC/SUB/SBC/INC/DEC handler correctly sets H and N.

### 3.3 Per-instruction flag matrix changes vs 8080

| Instruction(s) | 8080 flags | LR35902 flags |
|----------------|-----------|----------------|
| INC r / INC (HL) | Z, S, P, AC (C unchanged) | Z, N=0, H (C unchanged) |
| DEC r / DEC (HL) | Z, S, P, AC (C unchanged) | Z, N=1, H (C unchanged) |
| ADD/ADC | Z, S, P, AC, C | Z, N=0, H, C |
| SUB/SBC/CP | Z, S, P, AC, C | Z, N=1, H, C |
| AND | Z, S, P, AC=(A.3│r.3), C=0 | Z, N=0, **H=1**, C=0 |
| OR/XOR | Z, S, P, AC=0, C=0 | Z, N=0, H=0, C=0 |
| RLC/RRC/RAL/RAR (accumulator forms 0x07/0F/17/1F) | C only | **Z=0**, N=0, H=0, C |
| CB-prefixed RLC/RRC/RL/RR/SLA/SRA/SRL/SWAP | n/a | Z=result, N=0, H=0, C=shifted-out |
| BIT n,r | n/a | Z=!bit, N=0, H=1, C unchanged |
| ADD HL,rr | C only | N=0, H (bit 11), C (bit 15); **Z preserved** |
| ADD SP,r8 | n/a | **Z=0**, N=0, H (bit 3 of low byte), C (bit 7 of low byte) |
| LD HL,SP+r8 | n/a | Same flag rules as ADD SP,r8 |
| CPL | unchanged | N=1, H=1 set |
| SCF | C=1 only | C=1, N=0, H=0 |
| CCF | C^=1 only | C^=1, N=0, H=0 |
| DAA | additive only | N-aware (see §3.2) |

### 3.4 Helpers to write up front

Before touching any handler, add these on `Cpu` (or as static helpers):

- `SetZ(byte)`, `SetN(bool)`, `SetH(bool)`, `SetC(bool)`
- `SetFlags(byte result, bool n, bool h, bool c)` for ALU
- `Add8(byte a, byte b, bool carryIn)` returning result and setting Z/N/H/C
- `Sub8(byte a, byte b, bool carryIn)` likewise
- `AddHL(ushort rr)` for 16-bit ADD (bit-11/bit-15 flag math)
- `AddSpSigned(sbyte r8)` for 0xE8/0xF8 (low-byte 4-bit / 8-bit flag math)

Once those exist, every `ALU.cs` handler shrinks to 1–2 lines and gets the new
flags for free.

## 4. CPU control / interrupt model

### 4.1 IME (Interrupt Master Enable)

Replace `InterruptEnabled` semantics:

- LR35902 has **IME** plus the memory-mapped `IE` (0xFFFF) and `IF` (0xFF0F)
  registers. `Interrupt(byte opcode)` style RST injection (the 8080 way) does
  not exist — Game Boy interrupts are dispatched by reading `IE & IF` at the
  top of `Step()` and pushing PC + jumping to a fixed vector.

  Vectors:
  ```
  0x40 VBlank   bit 0
  0x48 LCD STAT bit 1
  0x50 Timer    bit 2
  0x58 Serial   bit 3
  0x60 Joypad   bit 4
  ```

- Dispatch cost: 20 T (5 M-cycles) for the actual interrupt servicing
  (2 wait + push PC (8) + set PC = vector (4) — final timing depends on which
  reference you follow; the canonical numbers are 5 M-cycles).

- `_pendingInterruptOpcode` / `Interrupt(byte)` should be removed; replace
  with an `IRequestInterrupt(InterruptType)` method that ORs into `IF`, or
  let the bus do that directly when peripherals fire.

### 4.2 EI / DI / RETI

- `EI` sets IME after the *next* instruction. The current
  `_enableInterruptsTimer` already implements this — keep it, but verify it
  is set to **1** so that exactly one instruction executes between EI and the
  IME being effective.
- `DI` clears IME immediately.
- `RETI` (0xD9) pops PC and sets IME=1 *immediately* (no one-instruction delay,
  unlike EI). New handler.

### 4.3 HALT bug

- If `IME=1` and an interrupt is pending: behavior matches 8080-style HALT —
  resume and service the interrupt.
- If `IME=0` and `(IE & IF & 0x1F) != 0` at the time HALT executes: HALT does
  not actually halt; instead the **next byte after HALT is read twice** (PC
  fails to increment for one fetch). This must be modeled for accurate test
  ROM passes (e.g. `halt_bug.gb`).
- If `IME=0` and no interrupt pending: HALT halts normally; CPU resumes when
  any enabled interrupt becomes pending, *without* dispatching it.

### 4.4 STOP

- 2-byte opcode `10 00`. Halts CPU and LCD until a button is pressed (joypad
  interrupt). Also used to switch CGB speed mode (out of scope for DMG).
- Implementation: consume the second byte (don't execute it), set a `Stopped`
  flag, exit on joypad input.

## 5. Things to remove from the existing core

- `IIOBus.cs` — Game Boy has no separate I/O bus; all I/O is memory-mapped
  on `IMemoryBus` at `0xFF00–0xFF7F`. Drop the field, drop `In`/`Out`.
- `Cpu.Io.cs` — delete after IN/OUT removal.
- `_isInterruptPending` / `_pendingInterruptOpcode` / public `Interrupt(byte)` —
  replace with `IF` register handling on the bus (see §4.1).
- All "undocumented alias" entries in the `Execute` switch (0x08, 0x10, 0x18,
  0x20, 0x28, 0x30, 0x38, 0xCB, 0xD9, 0xDD, 0xED, 0xFD) — they all become real
  instructions or illegal opcodes on LR35902.
- The existing 8080 dispatch arms for 0x22 (`Shld`), 0x2A (`Lhld`), 0x32 (`StA`),
  0x3A (`LdA`), 0xE0 (`Rpo`), 0xE2 (`Jpo`), 0xE8 (`Rpe`), 0xEA (`Jpe`), 0xF0 (`Rp`),
  0xF2 (`Jp`), 0xF8 (`Rm`), 0xFA (`Jm`) — these opcode bytes survive but encode
  different LR35902 instructions (see the **Replace** rows in §1). Remove or
  rewrite these switch arms; do not let the old 8080 handlers run.
- `Cpu.Lhld.cs`, `Cpu.Shld.cs`, `Cpu.LdA.cs`, `Cpu.StA.cs` — opcodes are reused
  for `LD A,(HL+/-)` / `LD (HL+/-),A` / `LD A,(a16)` / `LD (a16),A`. Either
  rename and rewrite or delete and replace.
- `Cpu.Special.cs` — keep the file, but remove `Xchg` and `Xthl`.
- The `P` and `S` constants in `CpuFlags` and any helper that touches them.

## 6. Suggested order of work

1. Rewrite `CpuFlags.cs` (§3.1) and add the flag helpers (§3.4). This will
   break every ALU handler — fix them as you go.
2. Delete IN/OUT/XCHG/XTHL handlers and the `IIOBus` plumbing.
3. Replace the 21 reused opcodes (§1, all "Replace" rows) — this is where most
   new behavior lives.
4. Add the CB prefix path and the 11 CB operations (§2). Drive them via the
   `(operation, operand)` decoder, not 256 case arms.
5. Rewrite the interrupt model (§4) — `IF`/`IE` polling, `RETI`, EI delay,
   HALT bug, STOP.
6. Re-implement DAA (§3.2).
7. Run Blargg's `cpu_instrs` test ROM. Fix what fails.

### 6.1 Post-boot register state (DMG)

If you skip the boot ROM, initialize the CPU as if the boot ROM has just
finished. The standard DMG values (matching what `cpu_instrs` and most test
ROMs expect at entry to `0x0100`) are:

```
PC = 0x0100
SP = 0xFFFE
AF = 0x01B0   (A=0x01, F=Z|H|C — N is clear)
BC = 0x0013
DE = 0x00D8
HL = 0x014D
IME = 0
```
